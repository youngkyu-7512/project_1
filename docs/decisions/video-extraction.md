# 동영상 추출과 로컬 저장

## Decisions

- 주어진 주소에서 동영상을 찾고 내려받는 일은 `yt-dlp`에 맡깁니다. 페이지 HTML을 직접 파싱해 동영상 주소를 찾지 않습니다.
- 분리된 영상 스트림과 소리 스트림의 병합은 `ffmpeg`으로 합니다. 사용자에게 제시하는 화질 선택지는 영상과 소리가 함께 담긴 결과물을 기준으로 합니다.
- `yt-dlp`와 `ffmpeg`의 실행 위치는 `PATH` 조회에 의존하지 않고 명시적으로 지정합니다.
- 유튜브 플레이어 클라이언트를 특정 값으로 고정하지 않습니다. `yt-dlp`의 기본 폴백 체인을 그대로 씁니다.
- 차단을 우회하지 않습니다. 계정 쿠키 주입, PO 토큰 수급, 프록시 우회는 쓰지 않고, 막히면 막혔다고 사용자에게 알립니다.
- 파일 저장은 브라우저가 아니라 앱의 로컬 서버 프로세스가 실제 경로에 수행합니다.
- 이 앱은 사용자 PC에서 실행하는 것을 전제로 합니다. 공개 서버에 배포하지 않습니다.

## Boundaries

- 사용자가 권리를 갖거나 다운로드가 허용된 콘텐츠를 대상으로 합니다. 플랫폼 약관이 금지하는 사용까지 승인하는 결정이 아닙니다.
- 로그인·쿠키가 필요한 비공개 콘텐츠는 이 결정이 다루지 않습니다. 자격 증명을 다루려면 별도 결정이 필요합니다.
- 동영상이 아닌 일반 파일 다운로드에는 적용하지 않습니다.
- 외부 바이너리를 쓴다는 사실이 그 도구의 모든 기능을 제품 표면에 노출해도 된다는 뜻은 아닙니다.

## Why

주요 스트리밍 플랫폼을 지원해야 한다는 요구가 있었고, HTML을 직접 파싱하는 방식은 `<video>` 태그 수준을 넘어서지 못해 이 요구를 충족할 수 없습니다.

`ffmpeg`은 선택이 아니라 전제입니다. 검증한 YouTube 영상은 영상과 소리가 합쳐진 progressive 포맷이 하나도 없었고, 병합 없이는 소리 있는 파일을 아예 만들 수 없었습니다.

브라우저 샌드박스는 사용자가 고른 폴더의 절대 경로를 제공하지 않습니다. "어느 폴더에 저장되었는지 보여주고 그 폴더를 연다"는 요구는 로컬 서버가 저장을 수행할 때만 성립합니다.

로컬 서버가 임의 경로에 파일을 쓰고 임의 주소를 조회하는 구조이므로, 공개 배포는 이 설계의 전제를 벗어납니다.

## Reconsider when

- `yt-dlp` 유지보수가 멈추거나, 지원해야 할 사이트를 더 이상 다루지 못하는 상태가 반복될 때
- 지원 대상이 자체 호스팅 페이지로 좁혀져 외부 바이너리 설치 부담이 이득보다 커질 때
- 저장 위치 표시와 폴더 열기 요구가 사라져 브라우저만으로 충분해질 때
- 여러 사용자가 함께 쓰는 형태가 요구되어 로컬 실행 전제가 무너질 때

## Still-rejected alternatives

- 순수 Node HTML 파싱 — `<video>`/`<source>`/`og:video`/HLS 수준만 다뤄 스트리밍 플랫폼에서 실패합니다. 지원 대상이 자체 호스팅 페이지로 좁혀지면 재검토합니다.
- 브라우저 File System Access API로 저장 — 디렉터리 핸들만 주고 절대 경로를 주지 않아 저장 위치 표시와 폴더 열기가 불가능하고, Chromium 계열 전용입니다. 두 요구가 사라지면 재검토합니다.
- progressive 포맷만 받아 `ffmpeg` 의존을 피하는 방식 — 검증 영상에서 해당 포맷이 0개였습니다. 대상 사이트가 progressive를 안정적으로 제공한다는 근거가 생기면 재검토합니다.
- `PATH`에 의존한 외부 바이너리 호출 — 설치 직후 갱신되지 않은 환경에서 실패했습니다.
- `player_client`를 `mweb` 등 특정 값으로 고정하는 방식 — 기본 폴백 체인이 사라져 오히려 받을 수 있는 화질이 사라집니다. 고정이 이득이라는 측정 결과가 나오면 재검토합니다.
- 차단 우회로 성공률을 올리는 방식 — 플랫폼의 이용약관을 어기고 사용자 계정이 정지될 수 있으며, 이 제품이 감당할 범위를 넘어섭니다.

## Evidence worth preserving

- `yt-dlp 2026.08.19`로 검증한 YouTube 영상(`aqz-KE-bpKQ`)은 포맷 53개 중 영상과 소리가 합쳐진 것이 0개였습니다.
- 같은 영상에서 1080p60은 정확한 크기(245.7MB)가 오지만, 4K(`628`)와 1440p(`623`) 등 DASH/HLS 기반 포맷은 크기가 `null`입니다. 근사치만 오는 포맷도 있어, 용량을 항상 제시할 수 있다고 전제하면 안 됩니다.
- `ffmpeg`이 설치되어 있어도 `PATH`에 없으면 `yt-dlp`가 `ERROR: You have requested downloading the video partially, but ffmpeg is not installed`로 중단합니다. 실행 위치를 명시해 해결했습니다.
- winget 기준 설치 식별자는 `yt-dlp.yt-dlp`와 `Gyan.FFmpeg`이며, 실행 파일 별칭은 `%LOCALAPPDATA%\Microsoft\WinGet\Links`에 놓입니다.
- 병합 결과의 확장자는 코덱에 따라 달라집니다. 검증에서는 av01+opus 조합이 `.webm`으로 나왔습니다.
- 같은 영상으로 `player_client`를 하나씩 고정해 측정한 결과입니다. 지정하지 않았을 때만 4K(`401+251`)를 가져왔습니다.

  | 지정한 클라이언트 | 결과 |
  | --- | --- |
  | 지정 안 함 (기본 폴백) | 성공, `401+251` 선택 |
  | `mweb` | 실패. `mweb client https formats require a GVS PO Token which was not provided` |
  | `web` · `tv` · `tv_simply` · `ios` · `web_safari` · `web_embedded` | 전부 exit 1 |
  | `android_vr` | 성공하지만 포맷 5개, 최대 360p, 병합 포맷 0개 |

- `yt-dlp --list-extractors` 기준 지원 사이트는 1,752곳입니다. 이 숫자는 버전마다 달라지므로 화면에 적을 때는 다시 측정해야 합니다.
