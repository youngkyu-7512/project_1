# 동영상 다운로더

## 사용자에게 돌아가는 결과

공유 비밀번호로 로그인한 뒤, 동영상이 있는 웹 페이지 주소를 붙여넣으면 받을 화질을 직접 고르고, 완성된 파일을 브라우저 다운로드로 받습니다. 받을 수 없는 경우에는 왜 안 되는지를 원인별로 구분해서 알려 줍니다.

## 범위

포함합니다.

- 공유 비밀번호로 로그인. 로그인하지 않으면 어떤 기능도 쓸 수 없습니다.
- 동영상 하나를 가리키는 주소 입력과 초기화
- 주소에서 제목·재생시간·스냅샷·화질 선택지 추출
- 화질 선택지 목록에서 하나 고르기
- 다운로드 진행 상태 표시
- 완성된 파일을 브라우저 다운로드로 받기
- 지원하는 사이트 안내와, 그 안내가 성공을 보장하지 않는다는 표시
- 실패 원인을 구분한 안내

포함하지 않습니다.

- 재생목록·채널 주소 처리 (아래 "미룬 결정" 참고)
- 로그인·쿠키가 필요한 비공개 콘텐츠(대상 사이트 쪽 로그인). 자격 증명 취급은 별도 결정이 필요합니다.
- 자막, 스냅샷 이미지 파일, 소리만 추출하기. 이번 결과에 필요하지 않습니다.
- 다운로드 이력 보관, 여러 건 동시 처리, 이어받기
- 차단을 우회하려는 모든 수단. 계정 쿠키 주입, PO 토큰 수급, 프록시 우회는 범위 밖이며, 막히면 막혔다고 알리는 것으로 끝냅니다.
- 로그인 없는 공개 접근, 개별 계정(회원가입), 사용자별 기록 구분. [hosting-and-access](../../decisions/hosting-and-access.md)의 범위를 벗어납니다.
- 저장 폴더 지정, 최근 폴더, 폴더 열기. 파일은 서버가 아니라 브라우저가 직접 받으므로 다루지 않습니다.

## 수용 기준

화면 구성, 상태별 표현, 문구는 승인된 [prototype.html](prototype.html)을 기준으로 하되, 로그인 화면과 저장 폴더 관련 화면(3단계)은 이번 전환으로 새로 정의합니다. 이 스펙은 지켜야 할 행동만 적고, 배치와 문구 자체는 프로토타입에 둡니다.

### 로그인

- 비밀번호를 입력하지 않으면 주소 입력을 포함한 어떤 기능도 쓸 수 없습니다.
- 비밀번호가 틀리면 그 사실을 알리고 다시 입력할 수 있습니다.
- 한 번 맞으면 다시 입력하지 않고도 얼마간 계속 쓸 수 있습니다.

### 주소 입력

- 주소가 비어 있으면 다음 단계로 진행할 수 없습니다.
- 지우기 조작은 입력한 주소와 그 아래 추출 결과·선택·진행·결과 표시를 모두 처음 상태로 되돌립니다.
- 추출이 진행 중임이 화면에 드러나고, 그동안 같은 요청을 다시 시작할 수 없습니다.

### 지원하는 사이트 안내

- 주소를 넣기 전에도 어떤 사이트를 받을 수 있는지 확인할 수 있습니다.
- 안내에는 자주 쓰는 사이트와 전체 지원 개수가 함께 나옵니다.
- 목록에 없는 사이트도 시도할 수 있다는 사실이 안내에 드러납니다.
- **성공이 보장되지 않는 사이트는 목록에서 구별되어 보이고, 왜 실패할 수 있는지가 함께 적힙니다.** 현재 유튜브가 여기에 해당합니다.
- 안내는 닫을 수 있고, 닫으면 원래 하던 일로 돌아옵니다.

### 화질 선택

- 추출에 성공하면 제목, 재생시간, 스냅샷 하나가 목록 위에 한 번 표시됩니다. 스냅샷은 화질 선택지마다 반복하지 않습니다.
- 각 화질 선택지에 해상도, fps, 확장자, 예상 용량이 표시됩니다.
- 용량을 알 수 없는 선택지는 크기를 알 수 없음이 드러나고, 그래도 고를 수 있습니다.
- 근사치로만 아는 용량은 정확한 용량과 구분해 표시됩니다.
- 목록의 어떤 선택지를 골라도 영상과 소리가 함께 담긴 파일 하나가 만들어집니다. 소리 없는 결과가 나오는 선택지는 목록에 넣지 않습니다.
- 화질을 고르지 않으면 다운로드를 시작할 수 없습니다.
- **목록이 불완전할 수 있는 상황에서는 목록 위에 그 사실이 표시되고, 보이는 화질은 그대로 받을 수 있습니다.** 불완전한 목록을 완전한 것처럼 보여주지 않습니다.

### 다운로드 진행

- 화질을 고르고 다운로드를 시작하면, 서버가 받고 병합하는 동안의 진행 정도와 진행 중이라는 사실이 화면에 드러납니다.
- 진행 중에 표시하는 전체 용량은 화질 목록에서 보여 준 값과 같습니다.
- 진행 중에는 주소를 바꾸거나 새 추출을 시작할 수 없습니다.
- 취소 수단은 제공하지 않습니다. (임시 동작)
- 서버 쪽 처리가 끝나면 곧바로 브라우저 자체 다운로드로 이어집니다. 그 이후의 전송 진행률은 브라우저 자신의 다운로드 표시에 맡기고 이 화면이 따로 보여주지 않습니다.

### 결과 확인

- 성공하면 실제 파일 이름이 표시되고, 그 이름은 추측이 아니라 실제로 만들어진 이름입니다.
- 실패하면 실패했다는 사실과 사유 요약이 표시되고, 같은 주소로 다시 시도할 수 있습니다.

### 실패 원인 구분

아래 상황은 서로 다른 안내로 구별됩니다. 하나의 일반 오류로 뭉뚱그리지 않습니다.

- **로그인 실패** — 비밀번호가 틀렸습니다.
- **지원하지 않는 주소** — 동영상을 찾지 못했습니다. 재생목록·채널 주소도 여기에 해당합니다.
- **추출이 막힘** — 주소는 정상이지만 사이트가 자동 요청으로 보고 차단했습니다. 잠시 뒤 다시 시도할 수 있고, 계속 막히면 받을 수 없다는 사실까지 알립니다.
- **다운로드 실패** — 내려받거나 병합하거나 전달하는 중에 중단되었습니다. 어디까지 진행됐는지와 사유를 알립니다. 실행 시간 제한 초과도 여기에 포함됩니다.

### 상태 표현

- 대기, 진행 중, 비어 있음, 성공, 실패 상태가 모두 설계되어 있고 서로 구별됩니다.
- 좁은 화면에서도 주소 입력 → 화질 선택 → 진행 → 결과의 사용 순서가 보존됩니다.

## 확정된 제약

- 추출·병합 방식과 플레이어 클라이언트 고정 금지는 [video-extraction](../../decisions/video-extraction.md)를 따릅니다.
- 배포 위치(Vercel), 접근 범위(공유 비밀번호), 파일 전달 방식(Vercel Blob 경유)은 [hosting-and-access](../../decisions/hosting-and-access.md)를 따릅니다. 이 스펙은 그 계약을 다시 서술하지 않습니다.
- 화면 구성, component 선택, 시각 토큰, 상태 표현 문법은 [ui-composition](../../decisions/ui-composition.md)를 따릅니다.
- 용어는 [GLOSSARY](../../../GLOSSARY.md)의 정의를 따릅니다. 특히 "화질 선택지"와 "스냅샷"의 관계가 화면 구성을 결정합니다.
- 하나의 다운로드는 Vercel Hobby의 함수 실행 시간 제한(300초) 안에서 추출·병합·업로드까지 끝나야 합니다.
- 자바스크립트 런타임은 없어도 동작하지만, 없으면 화질 목록이 불완전해집니다.
- 사용자가 권리를 갖거나 다운로드가 허용된 콘텐츠를 대상으로 합니다. 플랫폼 약관상 제한이 있을 수 있다는 점은 제품이 대신 판단하지 않습니다.

## 가정

사실과 다르면 바꿔도 되는 선택입니다.

- 로그인 세션은 브라우저를 다시 열어도 일정 기간(예: 며칠) 유지됩니다. 로그아웃 기능은 두지 않습니다.
- 저장 파일 이름은 동영상 제목과 식별자를 함께 담습니다. 제목만으로는 서로 다른 영상이 같은 이름을 가질 수 있습니다.
- 화질 선택지는 해상도가 높은 것부터 보여줍니다.
- 한 번에 하나의 다운로드만 진행합니다.
- 지원 사이트 안내에 이름을 직접 적는 사이트는 10여 곳이고, 나머지는 전체 개수로 갈음합니다.
- Blob에 올린 완성 파일은 일정 시간(예: 1시간) 뒤 자동으로 정리됩니다. 사용자가 그 안에 내려받지 못하면 처음부터 다시 시도해야 합니다.
- 로그인 실패 횟수 제한은 두지 않습니다.

## 미룬 결정

아직 확정하지 않았습니다. 임시 동작은 수용 기준에 "(임시 동작)"으로 표시했습니다.

- **재생목록·채널 주소 처리** — 개별 선택, 일괄 받기, 첫 영상만 중 무엇으로 할지 정하지 않았습니다. 그때까지는 지원하지 않는 주소로 안내합니다. "재생목록 처리 방식" 결정이 이 임시 동작을 대체합니다.
- **다운로드 취소** — 취소 중 임시 파일·Blob 정리 규칙까지 함께 정해야 합니다. 그때까지는 취소 수단을 제공하지 않습니다. "진행 중 작업 취소" 결정이 이 임시 동작을 대체합니다.
- **자바스크립트 런타임을 필수로 올릴지** — 지금은 포함하지 않고, 목록이 불완전할 수 있다는 사실을 알리는 것으로 끝냅니다. 근거와 다음 확인 절차는 [youtube-formats-missing-without-js-runtime](../../follow-ups/youtube-formats-missing-without-js-runtime.md)에 있습니다.
- **여러 건 동시 다운로드** — 한 사용자가 동시에 여러 건을 받는 것과, 여러 사용자가 동시에 각자 받는 것 모두 큐 없이 그대로 둡니다. 동시 요청이 늘어나 실행 시간·비용 문제가 실제로 확인되면 다시 정합니다.

## 남은 위험

- `yt-dlp`는 대상 플랫폼의 변경에 따라 특정 사이트가 예고 없이 실패할 수 있습니다. 유튜브가 특히 그렇고, 서버 IP는 가정용 회선보다 차단 대상으로 의심받기 쉬워 로컬 실행 때보다 더 자주 겪을 수 있습니다.
- 목록이 불완전하다는 사실을 제품이 항상 알아채지 못할 수 있습니다. 이 판단은 외부 도구가 내보내는 경고에 기대므로, 경고 형식이 바뀌면 경고 없이 불완전한 목록을 보여 줄 위험이 있습니다.
- 크기를 알 수 없는 화질 선택지가 흔합니다. 고화질일수록 크기가 비는 경향이 있어, 사용자가 용량을 근거로 고르려는 순간에 정보가 없을 수 있습니다.
- 매우 길거나 고화질인 영상은 추출·병합·업로드가 300초를 넘겨 실패할 수 있습니다. 이 스펙은 그런 영상을 나눠 받는 방법을 제공하지 않습니다.
- 정적 바이너리를 함수 배포에 포함하는 방식은 이 프로젝트에서 처음 시도합니다. 실행 권한이나 의존 라이브러리 문제로 실제 배포 환경에서 실패할 가능성이 있으며, 구현 중 실제로 확인해야 합니다.
- 공유 비밀번호 하나이므로, 유출되면 접근 범위 전체가 뚫리고 누가 유출했는지 구분할 방법이 없습니다.
- Blob 저장은 사용량에 따라 비용이 발생합니다. 실패한 다운로드나 받아가지 않은 파일이 쌓이면 비용도 함께 늘어납니다.
- 지원 사이트 안내는 시간이 지나면 실제 지원 범위와 어긋납니다. 개수와 목록을 언제 갱신할지는 정하지 않았습니다.
